# 告警监控移动端前端需求文档

## 1. 文档目标

本文档用于统一当前项目的产品范围、交互规则、页面职责、数据模型和维护边界。它面向两类读者：

- 继续迭代该项目的前端开发者
- 需要快速理解当前实现范围的产品、设计或评审人员

本文档描述的是“当前真实实现 + 可维护扩展方向”，不是抽象草案。

## 2. 产品背景

项目定位为移动端告警监控工作台，主要服务于需要在手机上快速完成系统巡检、趋势判断、告警定位和方法级下钻的场景。

核心设计诉求：

- 在小屏内承载高密度监控信息
- 保持告警与趋势信息的一致上下文
- 缩短从“异常发现”到“方法定位”的路径
- 保持前端演示版也具备真实可扩展的数据结构

## 3. 用户与使用目标

### 3.1 目标用户

- 运维值班人员
- 系统负责人
- 研发排障人员
- 演示或评审场景中的业务干系人

### 3.2 关键任务

用户通常需要在 1 至 3 分钟内完成以下动作：

1. 判断当前系统总体是否健康
2. 确认哪项核心指标存在波动
3. 查看当前时间范围内的趋势变化
4. 下钻到方法级别确认异常集中点
5. 查看当前系统告警及 AI 分析摘要

## 4. 页面范围

当前项目包含 3 个一级页面和 1 个二级工作区：

1. 系统总览
2. 系统详情
3. 告警列表
4. 方法拆分页

页面骨架规则：

- 顶部导航固定
- 底部分栏固定
- 中间内容区域独立滚动
- 方法拆分页打开后隐藏底部分栏，避免二级页面与一级导航冲突

## 5. 页面职责与交互

### 5.1 系统总览

目标：快速浏览所有系统状态，并进入单系统详情。

展示内容：

- 系统总数
- 系统筛选下拉
- 系统卡片列表
- 健康度
- 四个核心指标
- 微趋势图
- 接入来源标签

交互规则：

- 支持按系统名称筛选
- 点击系统卡片进入详情页
- 总览页保留顶部统计徽标，强化全局感知

### 5.2 系统详情

目标：在单系统上下文内完成指标查看、时间范围切换和趋势分析。

展示内容：

- 系统名称
- 业务域
- 接入来源
- 健康度
- 时间范围切换
- 指标总览
- 趋势分析
- 趋势统计摘要

关键交互：

- 切换时间范围时，趋势图、统计摘要、方法拆分页数据保持同源变化
- 指标总览默认展示重点指标，其余指标折叠
- `P50 / P90 / P99` 提供点击说明
- 趋势分析支持单图模式与多图模式切换
- 可直接进入告警页或方法拆分页

### 5.3 告警列表

目标：围绕当前系统查看告警记录，并按状态快速缩小范围。

展示内容：

- 告警筛选标签
- 时间线式告警列表
- 告警级别与状态标签
- AI 分析内容

交互规则：

- 默认折叠 AI 分析
- 支持按“全部 / 持续中 / 已解除 / 警戒 / 故障”筛选
- 切换系统时，重置局部筛选和展开态

### 5.4 方法拆分页

目标：对详情页趋势做方法级下钻，识别波动主要来源。

展示内容：

- 方法搜索
- 方法标签筛选区
- 多方法趋势图
- 最大值/最小值参考线
- 方法统计表

交互规则：

- 默认展示方差最大的前 5 个方法
- 支持 `全选 / 默认 / 清空`
- `全选 / 默认` 具备明确选中反馈
- 点击方法标签控制当前可见集合
- 点击方法名可切换单方法聚焦
- 点击表格最大值/最小值单元格可查看对应时刻
- 统计表支持 `最大值 / 最小值 / 均值 / 方差` 排序
- “已选 x 项”“方法统计”均提供解释提示

## 6. 关键体验规则

### 6.1 信息层级

- 总览页优先展示全局感知，不展示过深分析
- 详情页优先展示系统身份和趋势主分析区
- 拆分页只承接“继续分析”的任务，不重复系统级信息

### 6.2 移动端操作原则

- 关键操作尽量保证整块区域可点，而不是只靠小图标
- 下钻路径不超过两步：系统 -> 趋势 -> 方法
- 同类说明统一采用点击提示，不额外占据首屏空间
- 多图模式优先服务连续纵向阅读，不强制横向对比

### 6.3 视觉原则

- 基础主题为中性灰黑
- 高亮仅保留电蓝等少量功能性强调色
- 健康度数字使用金色，保持识别度
- 说明图标、下划线、边框应尽量克制，避免跳色

## 7. 数据模型与状态设计

### 7.1 根状态

`App.tsx` 统一维护：

- `activeTab`
- `selectedSystemId`
- `selectedMetric`
- `selectedRange`
- `pickerVisible`
- `pickerTarget`
- `splitPageVisible`
- `splitPageMeta`

设计原因：

- 保证所有页面使用同一系统上下文
- 保证趋势和拆分页共享同一指标与时间范围
- 避免跨页面重复状态导致回退和联动异常

### 7.2 模拟数据层

`src/data/mockData.ts` 负责：

- 系统模板
- 指标元信息
- 时间范围选项
- 总览指标
- 详情趋势
- 方法拆分序列
- 告警记录

模拟策略：

- 固定种子生成伪随机波动
- 相同系统 + 指标 + 时间范围组合下结果稳定
- 数据波形控制在“可解释、可演示、可对比”的范围内

### 7.3 类型约束

`src/types/monitor.ts` 定义核心领域类型，作为：

- 组件 props 契约
- 模拟数据输出契约
- 后续接接口时的结构参照

## 8. 技术实现原则

- 使用 `React` 管理视图状态
- 使用 `TypeScript` 保证数据结构明确
- 使用 `antd-mobile` 提供移动端基础交互组件
- 使用 `ECharts` 承接趋势图、拆分图和 tooltip 场景
- 使用单一 `global.css` 集中管理主题和页面样式

## 9. 当前实现相对原始需求的收敛

当前实现对常见“监控页需求清单”做了几项主动收敛，以适配手机端：

- 顶部系统筛选收敛为搜索下拉，不使用复杂筛选栏
- 指标总览采用“重点指标 + 展开更多”模式
- 说明文案采用点击提示，不长期占用版面
- 方法拆分从弹窗收敛为独立工作区，减少手势冲突
- 多图趋势切换为单列布局，优先保证纵向浏览

这些收敛不是删功能，而是为了：

- 压缩首屏高度
- 减少重复信息
- 提升单手操作命中率
- 降低移动端理解成本

## 10. 样式与代码维护要求

### 10.1 样式维护

- 当前主题以 `src/styles/global.css` 为唯一收口文件
- 保留当前生效主题，不继续堆叠过期视觉方案
- 优先复用现有变量、圆角、透明度和状态类名
- 能回收到样式表的视觉定义，不继续留在组件内联样式中

### 10.2 组件维护

- 组件尽量保持单一职责
- 复杂组件按“状态区 / 派生数据区 / 事件处理区 / 渲染区”组织
- 说明性注释只补在数据联动、状态切换和结构分区处
- 避免把复杂格式化逻辑直接写在 JSX 中

### 10.3 文档维护

- README 负责项目接入、结构和维护约定
- 需求文档负责范围、职责和交互规则
- 当页面交互发生变化时，优先同步 README 和需求文档

## 11. 验收清单

当前版本至少满足以下验收点：

- 总览、详情、告警三页可正常切换
- 未选系统时不能直接进入详情/告警
- 系统卡片可进入详情
- 详情页支持切换时间范围和趋势指标
- 详情页支持进入告警页和方法拆分页
- `P50 / P90 / P99` 支持提示说明
- 多图趋势模式可正常切换
- 方法拆分页支持搜索、多选、默认前五项展示和排序
- 告警页支持筛选和 AI 分析展开
- `npm run build` 可通过

## 12. 后续演进建议

1. 将接入来源标签色映射提取为共享常量，减少重复维护。
2. 将 `global.css` 按主题、布局、页面模块逐步拆分。
3. 接入真实接口后增加数据获取层，而不是在组件内直接请求。
4. 若后续引入更多页面，建议加路由并把拆分页升级为独立路由页。
