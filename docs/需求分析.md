# 银行系统移动端监控页面需求分析

## 1. 文档目的

本文档用于说明当前项目的需求边界、页面结构、交互规则、数据模型与维护策略，方便后续开发者快速接手并继续演进。

## 2. 业务目标

项目面向“银行系统移动端监控”场景，目标是让用户在手机端快速完成以下任务：

- 查看全部系统当前运行健康状态
- 进入指定系统，观察核心指标与趋势变化
- 查看系统告警与 AI 分析结果
- 在趋势异常时继续下钻到方法级拆分图

设计方向：

- 中文界面
- 暗色系
- 运维、银行、科技、专业
- 强调信息密度与移动端可读性

## 3. 页面结构

项目采用单页应用结构，包含三大一级分栏和一个二级拆分页：

1. 总览
2. 详情
3. 告警
4. 方法拆分页

页面框架规则：

- 顶部导航固定
- 底部分栏固定
- 中间内容区域滚动
- 方法拆分页为独立工作区，进入后隐藏底部分栏

## 4. 页面职责拆解

### 4.1 总览页

职责：

- 展示所有监控系统的当前状态
- 支持按系统名称搜索与筛选
- 为进入详情页提供入口

展示内容：

- 系统名称
- 业务域
- 接入来源标签
- 健康度
- 四个黄金指标
- 每个指标对应迷你趋势图与均值虚线

交互规则：

- 点击系统卡片，自动跳转到系统详情
- 切换系统筛选后，只显示符合条件的系统卡片

### 4.2 详情页

职责：

- 展示单系统的关键指标总览
- 提供时间范围与指标维度切换
- 提供告警页与方法拆分页入口

展示内容：

- 当前系统名称
- 业务域与接入来源
- 健康度
- 指标总览
- 趋势分析
- 趋势统计摘要

交互规则：

- 未选系统时不可直接进入
- 时间范围切换会同时影响：
  - 指标总览
  - 趋势图
  - 趋势统计摘要
  - 方法拆分页的数据范围
- 点击方法拆分图入口，进入方法拆分页

### 4.3 告警页

职责：

- 展示单系统的告警记录
- 支持按状态/级别筛选
- 提供 AI 分析展开查看

展示内容：

- 告警状态
- 告警级别
- 告警标题
- 告警内容
- 告警时间
- AI 分析

交互规则：

- 默认折叠 AI 分析
- 点击筛选标签后更新列表
- 切换系统后重置筛选与展开状态

### 4.4 方法拆分页

职责：

- 对详情页趋势图做方法级拆分分析
- 支持多选筛选、单方法聚焦与统计表联动

展示内容：

- 方法搜索
- 方法多选筛选标签
- 方法趋势图
- 最大值/最小值参考线
- 方法统计表

交互规则：

- 默认展示方差最大的前 5 个方法
- 点击筛选标签，控制当前显示的方法集合
- 点击表格中的方法名，可聚焦该方法的单条趋势
- 点击最大值/最小值单元格，可查看对应时刻

## 5. 状态与数据流设计

### 5.1 根状态

根组件 `App.tsx` 统一持有以下状态：

- 当前分栏 `activeTab`
- 当前系统 `selectedSystemId`
- 当前指标 `selectedMetric`
- 当前时间范围 `selectedRange`
- 方法拆分页开关 `splitPageVisible`
- 系统选择弹层状态 `pickerVisible`

这样做的原因：

- 保证总览、详情、告警、拆分页使用同一份当前系统上下文
- 保证时间范围和指标切换可以跨组件联动
- 避免多个页面各自维护系统状态，造成同步问题

### 5.2 模拟数据层

`mockData.ts` 负责：

- 定义系统模板
- 定义指标元信息
- 定义时间范围
- 生成总览指标
- 生成详情趋势
- 生成方法拆分序列
- 生成告警列表

模拟策略：

- 使用固定种子算法生成伪随机波动
- 同一系统 + 指标 + 时间范围组合，每次刷新趋势稳定
- 数据波形尽量贴近真实监控场景

## 6. 技术选型说明

- `React`：适合状态驱动式界面构建
- `TypeScript`：提升类型约束与维护性
- `Vite`：构建轻量，开发速度快
- `Ant Design Mobile`：提供移动端弹层、搜索栏、标签、分栏等基础能力
- `ECharts`：覆盖单序列、多序列、参考线和复杂 tooltip 场景

## 7. 当前实现与原始需求差异

为提升移动端可用性，当前实现对原始需求做了若干收敛：

- 总览页顶部筛选压缩为单个可搜索下拉
- 方法拆分图从弹窗改为独立页面
- 指标总览采用“重点指标 + 展开更多”的方式控制首屏高度
- 告警卡片 AI 分析默认折叠
- 多处标题与说明文案做了去重处理，优先展示有效信息

这些调整的目标不是减少功能，而是：

- 减少重复信息
- 提高一屏可见内容
- 降低移动端操作成本

## 8. 维护建议

### 8.1 组件维护建议

- 复杂组件优先保持“状态区 / 派生数据区 / 事件处理区 / 渲染区”的结构
- 不要把格式化逻辑直接写在 JSX 中
- 不要把模拟数据逻辑散落到组件内

### 8.2 数据层维护建议

- 若接入真实接口，建议保留 `types/monitor.ts` 作为接口契约层
- 若 mock 数据继续增长，建议把 `mockData.ts` 拆成多个模块

### 8.3 样式维护建议

- `global.css` 已按模块分区，后续新增样式时应放入对应区域
- 优先复用已有变量、圆角、边框、色值与间距节奏
- 避免继续堆叠多层边框，保持暗色玻璃态的整体统一

## 9. 验收清单

当前项目应满足以下验收点：

- 总览、详情、告警三页可切换
- 未选系统时详情/告警无法直接进入
- 总览点击卡片可进入详情
- 详情可切时间范围、切指标、进告警、进方法拆分页
- 方法拆分页支持搜索、多选、聚焦与表格联动
- 告警页支持筛选和 AI 分析展开
- 页面语言为中文
- 构建命令 `npm run build` 可通过
